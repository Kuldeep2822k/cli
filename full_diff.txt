+# CI/CD + Dependency Management Architecture Proposal for PALEE
+
+## Executive Summary
+
+This document presents the consolidated architecture, security specifications, and implementation roadmap for the PALEE CLI CI/CD automation and dependency management system. Based on an audit across 25 operational domains, this proposal adapts production engineering standards from mature Node.js CLI projects (such as GitHub CLI, ESLint, and pnpm) to create a pipeline that is **predictable, fast, supply-chain secure, capability-aware, and easy to maintain**.
+
+---
+
+## 1. Plan-Aware Security & Capability Matrix
+
+PALEE currently resides in a private GitHub repository. Feature availability depends on repository visibility and GitHub plan entitlements. The pipeline distinguishes features available immediately from those requiring public repository visibility or specific plan tiers.
+
+```text
+                                  PALEE CI/CD
+                                       │
+                ┌──────────────────────┴──────────────────────┐
+                ▼                                             ▼
+        Available Now                            Plan / Visibility Dependent
+   ┌──────────────────────┐                   ┌──────────────────────┐
+   │ • ESLint & typecheck │                   │ • CodeQL SAST        │
+   │ • Matrix unit tests  │                   │ • Dependency Review  │
+   │ • CLI integration    │                   │   Action (diff gate) │
+   │ • Tarball pack &     │                   │ • Artifact Attestations│
+   │   exact install test │                   │   & SBOM             │
+   │ • Refined native     │                   │ • Environment required│
+   │   toolchain guard    │                   │   reviewers          │
+   │ • npm audit          │                   │ • npm provenance     │
+   │ • npm ci lock check  │                   │   (Public repo only) │
+   │ • npm OIDC Trusted   │                   │                      │
+   │   Publishing*        │                   │                      │
+   └──────────────────────┘                   └──────────────────────┘
+```
+
+* **npm Trusted Publishing (OIDC)**: Recommended for private repositories. Replaces long-lived static `NPM_TOKEN` secrets. Requires Node >= 22.14.0 and npm >= 11.5.1 on release runners.
+* **npm Provenance (`--provenance`)**: Generated for public packages originating from public repositories. For private repositories, OIDC authentication is supported but npm provenance is unavailable.
+* **Fallback Security**: If CodeQL or Dependency Review are unavailable under the repository's plan, CI retains full security coverage using dual-scope `npm audit` (production PRs vs. full scheduled scans), strict lockfile verification (`npm ci`), inline license policy checks, and native toolchain policy guardrails.
+

+## 2. Core Policies & System Invariants
+
+### 2.1 PALEE Portability Policy (Native Modules)
+- **Policy**: PALEE's production runtime tree MUST install friction-free across Windows, macOS, and Linux without requiring host-side C/C++/Rust compilation suites (`node-gyp`, Python, MSVC).
+- **Rule**: Production dependencies should be pure JavaScript/TypeScript. Proposed native dependencies are rejected by default unless explicitly audited, cross-platform verified, and approved by repository maintainers.
+
+### 2.2 Lockfile Consistency Invariant
+- **Rule**: `package.json` and `package-lock.json` MUST remain 100% synchronized at all times.
+- **Enforcement**: Workflows execute strictly `npm ci`. Running `npm install` in CI as a substitute for `npm ci` is prohibited.
+
+### 2.3 Exact Tarball Pre-Publish Verification Invariant
+- **Rule**: Never publish an artifact that has not been installed and executed directly from the exact `.tgz` tarball generated by `npm pack`.
+- **Pipeline Flow**: Tag Version Check (`vX.Y.Z` == `package.json`) ➔ `npm run build` ➔ `npm pack` (Linux) ➔ Dynamic Tarball Assertion ➔ Download `.tgz` on Windows ➔ `npm install ./palee-vX.Y.Z.tgz` ➔ Global binary execution check (`EXPECTED == ACTUAL` on `palee --version` & `palee --help`) ➔ Pin npm 11.5.1 ➔ `npm publish`.

+## 4. Main PR Validation (`ci.yml`) & Scripting

+### 4.1 Script Separation & Rationale for Asset Copying
+In `package.json`, static typechecking (`tsc --noEmit`) and AST code linting (`eslint`) are explicitly separated:
+
+```json
+"scripts": {
+  "typecheck": "tsc --noEmit",
+  "lint": "eslint . --ext .ts",
+  "check": "npm run typecheck && npm run lint",
+  "build": "tsc && node -e \"require('fs').copyFileSync('package.json', 'dist/package.json')\"",
+  "test": "node --import tsx --test \"test/**/*.test.ts\"",
+  "test:coverage": "c8 npm test"

+```
+
+* `bin/palee.ts` imports `../package.json` for CLI version metadata (`program.version(packageJson.version)`). When compiled to `dist/bin/palee.js`, `import` compiles to `require('../package.json')`, which resolves to `dist/package.json`. Copying `package.json` into `dist/` fulfills this runtime module import.

+### 4.2 PR Concurrency & Cancellation
+PR validation cancels stale in-progress runs when a developer pushes new commits:

+```yaml
+concurrency:
+  group: ci-${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}
+  cancel-in-progress: ${{ github.ref != 'refs/heads/main' }}
+```

+## 6. Testing, Coverage & Flakiness Policies
+
+### 6.1 Category-Based Coverage Targets
+
+Coverage targets reflect code category responsibilities:
+
+```text
+Deterministic Pure Engine Logic (~90%+ Coverage Target)
+  ├── SM-2 algorithm math, bounds, rounding, and intervals (src/engine/sm2.ts)
+  ├── Topic mastery weighted formulas & status logic (src/engine/mastery.ts)
+  ├── 3-color DFS cycle detection & topological sorting (src/engine/dependency.ts)
+  └── CST YAML frontmatter parser byte-preservation (src/storage/frontmatter.ts)
+
+Integration & Filesystem Behaviors (Tested via Fixture Vaults)
+  ├── Multi-process file lock contention & heartbeats (src/storage/lock.ts)
+  ├── Optimistic Concurrency Control & atomic writes (src/storage/atomic-write.ts)
+  ├── Safe vault walker directory traversal (src/storage/vault-walker.ts)
+  └── Subprocess CLI execution, exit codes 0-5, and --json output (bin/palee.ts)
+```
+
+### 6.2 Realistic Incremental Coverage Thresholds (`.c8rc.json`)
+
+```json
+{
+  "all": true,
+  "src": ["src"],
+  "include": ["src/**/*.ts"],
+  "exclude": ["test/**", "dist/**", "node_modules/**", "**/*.d.ts"],
+  "reporter": ["text", "lcov", "html", "json-summary"],
+  "check-coverage": true,
+  "lines": 75,
+  "statements": 75,
+  "functions": 75,
+  "branches": 70
+}
+```
+
+* **Ratcheting Strategy**: Global thresholds start at 75% line coverage and ratchet upward as integration test suites expand. Core modules in `src/engine/` maintain internal 90%+ thresholds. Note: `src/index.ts` is covered by behavioral integration tests rather than excluded.
+* **Changed-Code Quality Gate**: PRs combine global coverage checks (75%), changed-line coverage (`diff-cover --fail-under=90`), and targeted behavioral integration tests.
+
+### 6.3 Test Isolation & Flakiness Policy
+1. **Isolated Test Vaults**: Every filesystem test must operate inside a unique temporary directory (`fs.mkdtempSync`) and execute complete cleanup inside `finally` blocks. Tests must never share global lock files or state directories.
+2. **Flakiness Policy**: Test flakiness must NEVER be resolved by adding arbitrary `sleep()` delays or blind retries. Race conditions must be eliminated by injecting deterministic clocks, using mock filesystems, or retrying strictly on documented OS transient conditions (e.g. Windows file lock release delays).

+## 7. Cross-Platform Tarball Packaging Assertions
+
+Tarball structure inspection takes place on Linux packaging jobs to avoid OS-specific tar shell expansion issues on Windows. Windows jobs download the compiled `.tgz` artifact and verify global binary installation. Required paths are dynamically derived from `package.json` entrypoints.
+
+### 7.1 Dynamic Linux Packaging Inspection (`ci.yml` & `release.yml`)
+
+```javascript
+node -e "
+  const { execSync } = require('child_process');
+  const pkg = require('./package.json');
+  const tarList = execSync('tar -tzf palee-*.tgz', { encoding: 'utf8' }).split('\n');
+
+  const REQUIRED = [
+    'package/' + pkg.main,
+    'package/' + pkg.types,
+    'package/' + pkg.bin.palee,
+    'package/package.json',
+    'package/README.md',
+    'package/LICENSE'
+  ];
+  const FORBIDDEN = ['package/src/', 'package/test/', 'package/.github/', 'package/planning/', 'package/coverage/'];
+
+  for (const req of REQUIRED) {
+    if (!tarList.some(f => f.startsWith(req))) {
+      console.error('❌ Missing required tarball file:', req);
+      process.exit(1);
+    }
+  }
+
+  for (const forb of FORBIDDEN) {
+    if (tarList.some(f => f.startsWith(forb))) {
+      console.error('❌ Forbidden file detected in tarball:', forb);
+      process.exit(1);
+    }
+  }
+  console.log('✅ Dynamic tarball assertions passed cleanly.');
+"
+```

+## 8. Security Audits, Toolchain Guardrails & License Policy
+
+### 8.1 Dual-Scope `npm audit` Strategy
+- **PR CI (`ci.yml`)**: Runs `npm audit --omit=dev --audit-level=high` (focuses strictly on production runtime risks without blocking PRs on unexploitable dev tool advisories).
+- **Scheduled Security Workflow (`security.yml`)**: Runs full `npm audit --audit-level=high` (scans all production and development dependencies to catch potential build-time CI compromise risks).
+
+### 8.2 Native Build Toolchain Policy Guard
+Functions as a policy guardrail checking production manifests and binary files in `node_modules` for unapproved compilation tools or `.node` extensions:
+
+```javascript
+node -e "
+  const fs = require('fs');
+  const path = require('path');
+  const { execSync } = require('child_process');
+
+  const BANNED_TOOLCHAINS = new Set([
+    'node-gyp', 'node-pre-gyp', '@mapbox/node-pre-gyp',
+    'prebuild-install', 'napi-rs', '@napi-rs/cli', 'cmake-js', 'node-addon-api'
+  ]);
+
+  let prodTree;
+  try {
+    prodTree = JSON.parse(execSync('npm ls --omit=dev --json', { encoding: 'utf8' }));
+  } catch (e) {
+    prodTree = JSON.parse(e.stdout || '{}');
+  }
+
+  function extractPackages(node, found = new Set()) {
+    if (!node || !node.dependencies) return found;
+    for (const [name, pkg] of Object.entries(node.dependencies)) {
+      found.add(name.toLowerCase());
+      extractPackages(pkg, found);
+    }
+    return found;
+  }
+
+  const prodPackages = extractPackages(prodTree);
+  const detectedToolchains = [...prodPackages].filter(pkg => BANNED_TOOLCHAINS.has(pkg));
+
+  function findNodeFiles(dir) {
+    let results = [];
+    if (!fs.existsSync(dir)) return results;
+    for (const f of fs.readdirSync(dir, { withFileTypes: true })) {
+      const p = path.join(dir, f.name);
+      if (f.isDirectory()) results = results.concat(findNodeFiles(p));
+      else if (f.name.endsWith('.node')) results.push(p);
+    }
+    return results;
+  }
+
+  const nodeFiles = findNodeFiles('node_modules');
+
+  if (detectedToolchains.length > 0 || nodeFiles.length > 0) {
+    console.error('❌ Native Module Guardrail Violation Detected!');
+    if (detectedToolchains.length > 0) console.error('Forbidden Toolchains:', detectedToolchains);
+    if (nodeFiles.length > 0) console.error('Forbidden .node files:', nodeFiles);
+    process.exit(1);
+  }
+  console.log('✅ Native Guardrail Passed: Zero native build toolchains or .node binaries found in production tree.');
+"
+```
+
+### 8.3 Permissive Open-Source License Audit (`security.yml`)
+To prevent copyleft pollution when Dependency Review Action is unavailable on private repository plans, `security.yml` executes an inline license policy check on production dependencies:
+
+```javascript
+node -e "
+  const { execSync } = require('child_process');
+  const ALLOWED = new Set(['MIT', 'ISC', 'Apache-2.0', 'BSD-2-Clause', 'BSD-3-Clause', 'CC0-1.0', 'Unlicense']);
+
+  const raw = execSync('npm ls --omit=dev --json', { encoding: 'utf8' });
+  const tree = JSON.parse(raw);
+
+  function auditLicenses(node) {
+    if (!node || !node.dependencies) return;
+    for (const [name, pkg] of Object.entries(node.dependencies)) {
+      const license = pkg.license || 'UNKNOWN';
+      if (!ALLOWED.has(license)) {
+        console.error('❌ Prohibited or unapproved license detected in production dependency:', name, '->', license);
+        process.exit(1);
+      }
+      auditLicenses(pkg);
+    }
+  }
+
+  auditLicenses(tree);
+  console.log('✅ License Audit Passed: All production dependencies maintain approved permissive licenses.');
+"
+```

+### 9.1 Tiered Update Cadence & Cooldown Configuration

+### 9.2 PR Lockfile Diff Review & Failure Protocols
+- **PR Lockfile Triggers**: Dependency Review Action triggers on modifications to `package.json` AND `package-lock.json`.
+- **Human Review Checklist**: Assess maintainer identity changes, repository transfers, and unexpected transitive package expansions.
+- **Dependency CI Failure Protocol**: Failed security PRs must be triaged immediately with dedicated fix commits rather than silently closed. Failed major/minor updates produce a tracking issue if deferred.

+## 10. Release Concurrency, Idempotency & Failure Semantics
+
+### 10.1 Tag-to-`package.json` Pre-Release Version Verification
+Before building or packing, `release.yml` asserts that the release tag strictly matches `package.json`:
+
+```yaml
+      - name: Verify Tag matches package.json Version
+        run: |
+          TAG_VERSION="${GITHUB_REF_NAME#v}"
+          PKG_VERSION=$(node -p "require('./package.json').version")
+          if [ "$TAG_VERSION" != "$PKG_VERSION" ]; then
+            echo "❌ Version mismatch! Git tag is v$TAG_VERSION but package.json is $PKG_VERSION"
+            exit 1
+          fi
+```
+
+### 10.2 Pinned npm CLI Version & Clean Step Output Idempotency
+To guarantee reproducible release publishing, the release job explicitly pins the tested npm CLI version (`npm@11.5.1`). NPM publication idempotency is managed via clean step outputs:
+
+```yaml
+      - name: Pin tested npm CLI version for OIDC Publishing
+        run: npm install -g npm@11.5.1
+
+      - id: check-published
+        run: |
+          VERSION=$(node -p "require('./package.json').version")
+          if npm view "palee@${VERSION}" version >/dev/null 2>&1; then
+            echo "already_published=true" >> "$GITHUB_OUTPUT"
+            echo "⚠️ Version ${VERSION} is already published on npm. Skipping publish step."
+          else
+            echo "already_published=false" >> "$GITHUB_OUTPUT"
+          fi
+
+      - name: Publish to NPM Registry
+        if: steps.check-published.outputs.already_published != 'true'
+        run: npm publish palee-${{ needs.verify-and-pack.outputs.version }}.tgz --access public
+```
+
+### 10.3 Release Failure & Forward Recovery
+- **npm Immutability Rule**: Once a version (`palee@0.2.0`) is published to the npm registry, its tarball contents CANNOT be overwritten or replaced.
+- **Forward Recovery Protocol**: In the event of a critical post-release defect:
+  1. Do NOT attempt to delete or force-repush the release tag.
+  2. Issue `npm deprecate palee@0.2.0 "Critical defect detected; update to 0.2.1"`.
+  3. Apply fix commit to `main`.
+  4. Tag and publish forward patch release `v0.2.1`.
+
+### 10.4 Post-OIDC NPM Token Lockdown
+After OIDC Trusted Publishing is verified:
+1. Revoke static publishing `NPM_TOKEN` secrets from GitHub Secrets.
+2. In `npmjs.com` account security settings, configure **"Require 2FA and disallow tokens"** for package publishing.

+## 11. Security Boundaries & Operational Failure Modes
+
+```text
+                         UNTRUSTED PR
+                              │
+                              ▼
+                     Read-only CI only
+                              │
+               ┌──────────────┴──────────────┐
+               ▼                             ▼
+       Test / Build                     Security checks
+               │                             │
+               └──────────────┬──────────────┘
+                              ▼
+                            MERGE
+                              │
+                              ▼
+                        Protected main
+                              │
+                              ▼
+                     Protected release tag (vX.Y.Z)
+                              │
+                              ▼
+                     Release verification
+                              │
+                              ▼
+                     Protected environment (npm-release)
+                              │
+                              ▼
+                        OIDC ➔ npm
+```
+
+### Critical Security Boundaries
+1. **Fork / Untrusted PR Security Boundary**: `pull_request` triggers run code in a read-only environment without access to repository secrets or write tokens. Workflows must NEVER use `pull_request_target` with checked-out untrusted PR code and write permissions.
+2. **Workflow File Protection**: Any PR modifying `.github/workflows/**` requires mandatory maintainer review and explicit authorization.
+3. **Secret Isolation**: NPM publishing credentials (via OIDC tokens) are scoped exclusively to the `publish-npm` job inside the protected `npm-release` environment.
