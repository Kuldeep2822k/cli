- **2026-09-22 — plan 006 Step 0: Variant A (implement the bridge), authorized by
  the operator.** `--auto-chain` will span already-adopted notes inside the
  scanned scope as chain predecessors, while continuing to write nothing into

  (`palee_roadmap: true`)**, chosen over an explicit CLI flag and over refusing

  matches how `palee_id` / `palee_schema` already mark a note's role.

## Findings considered and rejected

Recorded so nobody re-audits them.

- **Roadmap import needs a rollback journal (my finding N5)** — rejected as
  specified. `agent.md:75` states the import "is transactional per-topic with
  partial-failure exit 1", so per-topic non-atomicity is a documented design
  choice, not a defect, and `adopt.ts`'s journal is not a pattern to copy here.
  Reframed follow-up (worth doing, not planned): after a partial roadmap import,
  run the existing engine helper `findMissingDependencies` over the merged graph
  and report dangling `depends_on` ids, so the user learns which edges point at
  notes the import did not create. Reuses a canonical helper; no new abstraction.
- **"Cycle detection over the auto-generated graph" (issue #73 criterion) is
  vacuous** — not a bug. `planAutoChain` emits one backward edge per node in a

  feature can generate, and mis-wired edges (001/003/004/006) are all acyclic, so
  none of them are caught. Folded into 007's doc pass implicitly.

- exact `.md` candidate is a **directory** — `dirnote/note.md/` made

- candidate is a **dangling symlink** — `existsSync` reads it as merely missing,

- a path component is a **regular file** (ENOTDIR below it) — `[[blocker.md/note]]`
  resolved `MODULES/note.md`.

`existsSync`, and never read a `realpathSync` failure as a missing ancestor
(that is what let dangling symlinks through).

**Deviation from CodeRabbit's suggested patch, recorded deliberately:** their
loop condition was `while (ancestor !== resolvedVault)` alone. `path.resolve`
resets the root for an absolute target, so a dirname chain that never passes
through `resolvedVault` would not terminate. Unreachable today (the lexical
`isWithinVault` guard throws first), but a loop should not depend on a distant
check to terminate — the filesystem-root guard was kept alongside it. This is
the second time a CodeRabbit *patch* was wrong while its *finding* was right
(the first was N-B's `hasUnnumbered` rule); verify the patch, not just the bug.
